# tp126 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5126>

端口固定为 `5126`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、标准偏移、是否实行夏令时、夏令时偏移、切换规则、生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名与偏移；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及生效年份填上
3. 换算台选好日期、时刻与来源时区，点换算一遍，页面列出每个已登记时区的当地日期、当地时刻、星期、与来源是否同一天、偏移以及跟来源时区差多少；点“存为换算方案并执行一遍”会把这次输入存成方案，结果挂在方案名下
4. 换算方案区列出每条方案的来源时区、执行次数与最近执行时间，可以查看历次结果、再执行一次或删除（删除方案会连带删掉它名下的结果）
5. 时区档案的“引用”列显示它被多少处用到，点“查看引用”能单独看到：哪些换算方案把它当来源时区、哪些换算结果以它为来源、它出现在哪些结果明细行里，三个计数分别与各自列表的条数一致，合计也对得上
6. 删除档案前必须先看清引用：有引用时二选一——把引用改派到另一条档案（方案与结果的来源时区改过去，被删档案的结果明细行移除），或者确认后连同引用一起清掉（删掉以它为来源的方案与结果，并从其余结果里移除它的明细行）；没有勾选确认、没选处理方式或处理方式不完整时，删除一律被服务端拒绝
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 删除的口径

- 删除接口在同一次读写里完成全部检查与落盘：先校验确认状态、处理方式、改派目标，全部通过后才改内存里的数据并一次性落盘；任何一步失败，磁盘上的数据都不变，不会留下删了一半的状态
- 改派（`mode: "reassign"`）必须带一条别的、确实存在的目标档案；以被删档案为来源的方案与结果把来源改到目标档案，结果里目标档案的行重新标为来源行，时差与跨天标记按目标档案的偏移重算
- 清除（`mode: "purge"`）会删除以被删档案为来源的方案与其全部结果，其它结果里只移除属于被删档案的明细行，结果本身保留
- 没有任何引用的档案，只要带确认即可删除，服务端按清除方式处理
- 引用计数的口径：方案引用（来源时区）+ 结果来源引用 + 结果明细行，三类分别计数，引用总数等于三者之和；档案列表上的引用数与引用查看接口给出的总数一致

## 换算口径

- 换算按登记的标准偏移进行：先把输入的当地时刻减去来源时区的标准偏移得到基准时刻，再逐个时区加上各自的偏移
- 每个时区的当地日期与时刻都由基准时刻加上该时区的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 与来源时区的时差按两边偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 结果按偏移从小到大排列，来源时区那一条在页面上会标出来
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 标准偏移与夏令时偏移都按整数分钟登记，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数（例如东五区半写 330、加德满都写 345）
- 实行夏令时的档案必须填夏令时偏移，且要比标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 生效年份填 1900 到 2100 之间；结束年份留空表示至今有效，已经停止实行夏令时的地区要把结束年份填上
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...], "plans": [...], "runs": [...] }`：`zones` 是时区档案，`plans` 是换算方案（以 `sourceZoneId` 引用档案），`runs` 是每次换算结果，记下来源时区引用（`sourceZoneId`）与每个时区的结果明细行（`rows[].zoneId`）。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。重新载入时发现方案或结果引用了已经不存在的档案，会把这类悬空引用丢掉。

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索，每条带引用计数 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案                               |
| GET    | /api/zones/:id/references | 查看这条档案的方案引用、结果来源引用与结果明细，三类计数与列表条数一致 |
| PATCH  | /api/zones/:id   | 修改档案                                   |
| DELETE | /api/zones/:id   | 删除档案；需在请求体里带 `confirm:true`，有引用时还要带 `mode`（`reassign` 时带 `targetZoneId`，或 `purge`）；缺确认或处理方式不完整时返回 409/400，响应体里附最新引用情况 |
| POST   | /api/convert     | 把一个时刻换算到所有已登记的时区，不留存  |
| GET    | /api/plans       | 换算方案清单                               |
| POST   | /api/plans       | 新建方案并立刻执行一遍，方案与首条结果一起落库 |
| GET    | /api/plans/:id   | 查看方案与它名下历次结果                 |
| POST   | /api/plans/:id/run | 按方案登记的输入再执行一次，结果追加到方案名下 |
| DELETE | /api/plans/:id   | 删除方案及其名下全部结果               |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上；删除前的 409 会额外带 `details.references`，页面据此展示引用清单。
